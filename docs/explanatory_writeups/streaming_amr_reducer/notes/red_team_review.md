# Red-Team Review

## Verdict

Streaming native AMR cells directly into additive histograms is the right
architecture for this one-off repair. The draft overstates the implementation
correctness case, especially for global AMR coverage and the 62 new science
products. The current evidence strongly validates the basic reducer path and
the original `edot_sph` controls. It does not yet validate every scientific
definition or prove that a complete input tessellates the domain exactly once.

## Prioritized Findings

### P0: The implemented AMR checks do not prove exact spatial coverage

The draft says a complete run rejects missing, duplicate, or overlapping
leaves and treats volume closure plus logical-key checks as exact domain
coverage. The implementation is weaker:

- it rejects duplicate logical keys;
- it rejects ancestor/descendant logical-key pairs;
- it sums physical block volumes;
- it does not verify logical-key bounds for each level;
- it does not verify physical geometry against the logical key and domain;
- it does not detect arbitrary same-level physical overlap;
- it does not detect a hole compensated by an extra equal-volume block.

`validate_chunk_metadata()` only requires nonnegative logical coordinates,
finite geometry, and positive extents. Therefore unique keys plus the correct
total volume are necessary but not sufficient for “covers the domain exactly
once.” The document currently claims a guarantee the code does not implement.

**What would make the conclusion wrong:** construct a synthetic full run with
one missing block and one distinct-key duplicate/extra block of equal volume.
If it passes global validation, the strong exact-coverage claim is false.

### P0: The evidence for the 62 science products is mostly self-consistency

The archived external controls exercise `output29` and `output31`, both using
`edot_sph`. They do not independently validate mass, volume, scalar, metal,
dust, Mach, vertical transport, angular momentum, or the other newly defined
science products. The one-block oracle exercises formulas, but it mirrors the
same intended definitions and uses a synthetic writer created with the same
project assumptions.

The hard-coded composition conversion, scalar interpretation, metal/dust
accounting, and thermal/enthalpy choices are scientific assumptions, not just
software mechanics. “The correctness case is strong” is defensible for the
streaming architecture and original repair path; it is too broad for all 76
products.

**What would make the conclusion wrong:** an independently specified
cell-sample calculation, using the simulation’s physical conventions rather
than the reducer reference module, disagrees with any science product’s
coordinate or weight definition.

### P1: The same-weight closure figure is close to a tautology

Every cell computes one weight and deposits it once into every product sharing
that weight. If binning is in range, totals must agree even when all products
share the same wrong weight formula, wrong cell volume, or wrong source cells.
The `10^-13` spread is useful for catching dropped deposits and reduction
errors, but it is weak evidence of physical correctness. The caption and text
call it a “strong internal accounting check”; readers may mistake it for an
external validation.

The figure generator also scales spread by the maximum absolute value of the
signed totals, while the full validator scales by maximum histogram absolute
sum. Those are different normalizations and should not be visually compared to
the same `2e-9` line without explanation.

**What would make the conclusion wrong:** deliberately change a shared weight
formula or cell volume by a common factor and observe that the closure figure
still passes. That would demonstrate the test cannot support the stronger
claim.

### P1: “Independent Python oracle” overstates independence

The Python oracle is separate code, which is valuable. It is not independent
evidence in the stronger scientific sense: its product catalog and formulas
closely mirror the C++ implementation, and its synthetic data are generated by
the same test package. A shared misunderstanding of legacy bin semantics,
field meaning, or units can pass both implementations.

The real archived controls reduce this risk for a narrow subset. They do not
remove it for the full product catalog.

**What would make the conclusion wrong:** a reference derived directly from
AthenaK’s online PDF implementation or a hand-calculated set of real cells
disagrees while the Python/C++ pair continues to agree.

### P1: “Fail-closed publication” depends on consumers honoring the manifest

Each header and payload is renamed from `.partial` to its final name before the
manifest is written. A failed run can therefore leave a directory containing
some final-looking product files and no manifest. The production analysis
reader can read those PDFs without checking `rebuild_manifest.json`.
Individual rename is atomic, but the whole product set is not atomically
published, and there is no shown `fsync` durability guarantee.

The design is fail-closed only for downstream workflows that explicitly
require a valid final manifest. The draft states the stronger property without
that condition.

**What would make the conclusion wrong:** interrupt a run after one product is
renamed and show that a normal downstream reader consumes the incomplete
directory as valid output.

### P1: The real-GPU evidence demonstrates execution, not bounded production behavior

The one-shard and eight-shard runs establish that the real format, CUDA path,
FP64 atomics, and small MPI reduction execute. They skip global AMR closure and
cover only four K80 GPUs. They do not test root metadata growth, 1024-rank
collectives, Frontier filesystem contention, MI250X atomics, or the all-product
path at real-snapshot scale.

The memory equation includes `O(N_blocks,r)` but understates rank-zero global
key gathering and output/reduction buffers. Those may still be acceptable, but
they are snapshot-size-dependent and should be quantified before saying the
snapshot size does not enter the dominant term.

**What would make the conclusion wrong:** a complete snapshot exhausts rank-zero
memory, stalls in global key gathering/reduction, or cannot finish within the
production walltime despite bounded chunk buffers.

### P2: The dense-cube alternative is attacked in its most wasteful form

A finest-resolution uniform cube is clearly infeasible and scientifically
unnecessary. That does not rule out every resampled or hierarchical
intermediate. A coarsened grid, distributed field transform, or per-level
reduction could be useful for selected diagnostics. The draft is correct for
the requested PDFs, but “the correct reduction architecture” should not be
read as a general result for all later analyses.

**What would make the conclusion wrong:** a required product is found that
depends on neighborhood operations, cross-cell topology, or a scale-defined
resampling and cannot be expressed as an additive per-leaf histogram.

## Required Changes Before Calling the Correctness Case Strong

1. Weaken exact-coverage language or add logical-key/domain/geometry
   consistency and same-level overlap checks.
2. Split the correctness claim into: streaming architecture, original repair
   products, and new science products.
3. Recast same-weight closure as a narrow deposit/reduction invariant.
4. State that publication is fail-closed only when consumers require the final
   manifest.
5. Add an independent real-cell sample audit for representative science
   products and quantify full-run root memory/collective costs.
