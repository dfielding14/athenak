## Claim Traceability

Supported:

- The code streams bounded chunks with `pread`, copies each chunk to the
  device, executes a Kokkos derive/bin kernel, performs product-wise
  `MPI_Reduce`, and publishes via `.partial` files followed by rename.
- The code performs global leaf uniqueness, ancestor-overlap, and
  domain-volume checks for complete input.
- The original product set uses `0.29188603162765503` GiB of histogram
  storage; all 76 products use `0.32479578256607056` GiB.
- One real K80 shard processed `83,886,080` cells and `2.50002622604` GiB in
  `99.685631315` seconds.
- The four-K80/eight-shard run processed `671,088,640` cells and
  `20.0002098083` GiB in `381.626483859` seconds.
- One block with all 76 products ran on a K80. Its manifest contains 76
  products and `262,144` processed cells.
- A fresh local CPU all-product run against the same first real block matched
  the preserved GPU output for all 76 payloads:
  `global_max_abs=1.27898e-13`, `global_max_rel=1.0749e-14`.
- The independent synthetic/reference suite was rerun and reported
  `6 passed in 153.55s`.
- The production analysis reader is exercised by the passing test suite.
- The draft correctly leaves full 1024-shard closure and MI250X performance
  unresolved.

Evidence boundary:

- "Bounded memory" follows from the implementation and memory formula, but no
  peak resident-memory measurement is preserved. The architectural claim is
  supported; it should not be read as a measured memory-performance result.
- The all-product CPU/GPU comparison generated by this audit lives in
  `/tmp/gotham-repro-audit.T5cDY9/cpu_one_block_all76`. The numerical result is
  recorded here, but the temporary payloads are not a durable project artifact.

No unsupported scientific metric was found beyond those explicitly labeled as
pending or as an analytical estimate. Exact provenance for the current
`same_weight_total_closure` artifact remains unresolved.
